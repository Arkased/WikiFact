# Manage wikis

Technical layer. The requirements are in [../requirements/wikis.md](../requirements/wikis.md). The design is in [../design/wikis.md](../design/wikis.md).

## Management tools of the service

The management endpoint of service mode has the 4 tools below and the 4 wiki tools of [search](lookup.md#search) to [requestChange](submit.md#requestchange), each with one added required argument, `wiki`, the name of the wiki from `listWikis`. One connection to `/mcp` therefore serves every wiki, and a session names the wiki in each call. An unknown name is a tool error. A wiki endpoint of [Wikis folder and mounting](wikis.md#wikis-folder-and-mounting) has the 4 wiki tools without the argument and none of the management tools. No tool needs a human step outside the session: the client's own permission prompt is the button, and the guardrails and the archive bound a call that goes through without one.

| Tool | Input | Output |
|---|---|---|
| `createWiki` | `name`: 1 to 40 lower-case letters, digits and hyphens. `subject`: the sentence every question gets, not empty. `quality` optional, a preset name of [Quality presets](questions.md#quality-presets). | `{ name, url, created }`. The same name with the same subject returns the existing wiki with `created: false`. The same name with another subject is a tool error that names the existing subject. A name whose normal form (lower case, hyphens removed, a final `s` removed) equals the normal form of an existing wiki is a tool error that names that wiki. A bad name, an empty subject, or a count at `--max-wikis` is a tool error that says so. |
| `archiveWiki` | `name` | `{ name, archivedTo }` or `{ name, removed: true }`. The wiki is unmounted and its worker stopped. A wiki with no fact at all (live or deleted) and 0 queued requests is removed. Any other wiki moves to `<wikis>/.archive/<name>-<stamp>/`, and a human restores it by moving the folder back. |
| `unarchiveWiki` | `name`, or the archive folder name `<name>-<stamp>` to pick one of several | `{ name, url }`. The folder moves back to `<wikis>/<name>/`, is mounted, and gets its worker. With several archives of one name, the newest is restored and the answer says so. A live wiki with that name, or an unknown archive, is a tool error. |
| `listWikis` | none | `wikis: Array<{ name, subject, url, liveFacts, queued, worker }>`, sorted by name, and `archived: Array<{ name, folder, archivedAt }>`. `worker` is `{ running: boolean, lastCall?: { ok, kind?, message?, at } }` from the status of [Queue and worker](updates.md#queue-and-worker), so a session sees whether the credential works before it submits. |

Tool annotations: `createWiki` and `unarchiveWiki` are `idempotentHint: true`, `destructiveHint: false`; `archiveWiki` is `destructiveHint: true`; `listWikis` is `readOnlyHint: true`. The 4 wiki tools carry the same kind of annotation (`search`, `getFact` and `getRequest` read-only; `requestChange` not destructive, not idempotent).

## Wikis folder and mounting

- Every subfolder of `--wikis` that holds a `wikifact.json` is a wiki. The server opens each one and mounts it at `http://127.0.0.1:7777/wikis/<name>/mcp`, with the 4 tools of [MCP tool contracts](lookup.md#mcp-tool-contracts) unchanged. The one connection most sessions need is the management endpoint. The WikiFact plugin of this repo (`plugin/`) holds its entry and the deploy adds none ([Service mode](deployment.md#service-mode)); a client without the plugin adds it by hand with `claude mcp add --scope user --transport http wikifact http://127.0.0.1:7777/mcp`, and a session with the plugin must not. On it the same 4 tools take a `wiki` argument ([Management tools of the service](wikis.md#management-tools-of-the-service)). A project that works on one wiki may pin it instead: `claude mcp add --transport http <name> http://127.0.0.1:7777/wikis/<name>/mcp`.
- The service starts with no wiki. The first wiki comes from `createWiki` or from a folder the operator adds.
- The management endpoint is `http://127.0.0.1:7777/mcp` with the 4 tools of [Management tools of the service](wikis.md#management-tools-of-the-service). `createWiki` writes `<wikis>/<name>/wikifact.json` with the mode of the service, creates the empty database, mounts the endpoint, starts the worker child, and returns the endpoint URL. `--max-wikis N`, default 10, caps the count. `archiveWiki` moves a wiki to `<wikis>/.archive/`, or removes it when it has no fact, live or deleted, and no queued request; a folder under `.archive/` is never mounted. `unarchiveWiki` moves it back and mounts it. No wiki is deleted with content in it, and an agent can undo its own archive.
