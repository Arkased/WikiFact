# Research: agent-maintained wikis and shared knowledge bases

Report from a research agent, 2026-10-03. Caveat from the agent: the fetch of the Karpathy gist mixed in comment-thread content, so its bullets cover only the core pattern.

## 1. Karpathy "LLM Wiki" gist (Apr 2026)

https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f

- Who writes: one LLM agent. A human picks the sources, sets direction and spot-reviews.
- Unit: markdown pages for entities, concepts and syntheses, with cross-links. Three layers: raw/ (immutable sources), wiki/, and a schema file such as CLAUDE.md.
- Changes: direct writes. "Ingest" reads one source and updates roughly 10-15 pages. "Query" answers from the wiki and can file good answers back as new pages.
- Quality: a periodic "lint" pass flags contradictions, stale claims, orphan pages and missing links. An index.md catalogs the pages. A log.md records every operation, append-only.
- Confidence and staleness: no per-fact fields. Staleness is found only by lint.
- Flagged as hard: silent capture failures, agents not consulting the wiki mid-task, and markdown being poor at showing how facts change over time.

## 2. Astro-Han/karpathy-llm-wiki (an implementation)

https://github.com/Astro-Han/karpathy-llm-wiki

- Who writes: one agent, packaged as a skill for Claude Code, Cursor and Codex.
- Unit: pages, plus a global index and an append-only log.
- Changes: direct writes during ingest.
- Contradictions: recorded next to each other when found, not resolved.
- Confidence: deliberately none. Numeric scores were judged "false precision with no calibration."
- After three months of logs, the author dropped staleness timers, review dates, access-based decay, source-hash freshness and vector search. Reason given: "frequently asked is not the same as true."
- Key finding: every fidelity error observed was a value that was not in the source, so citation checking is a simple grep.

## 3. "Beyond Memory" llm-wiki substrate (Moreira and Sweet, Notre Dame, 2026)

https://arxiv.org/html/2607.24759

- Who writes: humans plus agents. Every log entry carries "by: <human> via <agent>".
- Unit: small markdown pages with YAML frontmatter and typed edges (extends, supports, criticizes, source).
- Changes: direct appends. Pages are append-only by convention, and each log entry is one git commit.
- Quality: provenance through git blame. A "verification gate" requires every numeric claim to be backed by script output.
- A retroactive audit caught inflated claims: a reported 20 evidence-backed answers went to 14, then 18 after fixes.
- No staleness markers. History is kept instead of flagging age.
- Untested: several agents writing at once. Also open: injection of adversarial content, and no comparison against Notion or plain git.

## 4. Grokipedia (xAI)

https://thenextweb.com/news/grokipedia-frozen-no-edits-since-april-xai-musk , https://api.politifact.com/article/2025/nov/12/Grokipedia-Wikipedia-AI-citations

- Who writes: one model, Grok, writes every article. Readers can only suggest edits.
- Unit: encyclopedia articles.
- Changes: suggestions are reviewed by an AI, PR-style.
- By Dec 2025, AI-written suggestions were over three-quarters of all proposals. That means the writer, the checker and the editor were the same model.
- Failures: hallucinated citations, plagiarism and biased framing, worst on contested topics.
- The review queue froze with 13,002 suggestions pending and nothing decided for about three months.
- There is no public edit history.

## 5. Governed Shared Memory for multi-agent systems (2026)

https://arxiv.org/abs/2606.24535

- Who writes: many agents across tenants.
- Changes: one gate runs at write time and rejects near-duplicates. A separate contradiction detector runs later. "Temporal supersession" replaces old facts with newer ones.
- Provenance: derivation chains four steps deep were fully reconstructed, with the correct writer each time.
- Named failure modes: unauthorized leakage, stale propagation, contradiction persistence, provenance collapse.
- Found: scope rules were enforced unevenly, and the write-time gate and the later detector conflicted over ordering.

## 6. Collaborative Memory (2025)

https://arxiv.org/html/2505.18279v1

- Who writes: many users and agents.
- Unit: key-value memory fragments generated by an LLM.
- There is a private tier and a shared tier. Write policies can redact or anonymize a fragment before storing it.
- Each fragment's provenance cannot be changed: time, user, agents, and resources used. This allows permission checks after the fact.
- No confidence or staleness handling.
- Limits: tested only on synthetic data, enterprise-scale concurrency not studied, hallucination still possible.

## 7. Graphiti / Zep temporal knowledge graph

https://github.com/getzep/graphiti

- Who writes: agents, through automatic extraction.
- Unit: entity nodes plus fact edges (triples), each with a validity window. Every fact traces back to raw "episodes."
- Changes: the graph updates incrementally with each new episode.
- Contradictions are handled by invalidating the old fact, not deleting it, so history is kept.
- It tracks when a fact was true, not how confident the system is in it.
- Hard: dedup and entity resolution depend on structured LLM output, which small models often get wrong.

## 8. Stanford STORM / Co-STORM

https://github.com/stanford-oval/storm , https://arxiv.org/pdf/2408.15232

- Who writes: several expert agents, a moderator agent and an optional human.
- Unit: a mind map that updates live, then a cited article in Wikipedia style.
- The moderator steers the discussion. Every claim is cited to a retrieved source.
- It builds one report per session. Nothing is maintained over time.

## Common patterns and open problems

- Most systems have one agent writing directly. Real multi-writer concurrency is rarely tested.
- Raw sources are kept immutable, and every derived claim cites them. This is the most widely shared quality mechanism.
- Append-only logs or invalidation are preferred to deletion. History beats overwriting.
- Contradictions are mostly flagged, or left side by side, rather than resolved. Last-write-wins is widely rejected.
- Staleness is mostly handled by lint passes or validity windows. Per-fact confidence scores are rare, and some practitioners reject them outright.
- Review by the same model is weak, as Grokipedia shows. Independent checks work better: script output, quote verification, or human gates.
- Open problems:
  - Dedup and entity resolution at scale.
  - Agents ignoring the knowledge base mid-task.
  - Prompt injection through ingested sources.
  - Markdown handling change over time poorly.
  - Review queues becoming a bottleneck.
- Survey of the problem space: https://aaif.io/blog/agent-memory-patterns-tradeoffs-open-problems
